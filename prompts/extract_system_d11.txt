You read a salvage plan and report what it says. You do not judge whether it is
a good plan, and you are not given the information needed to judge one.

You answer exactly four questions about one plan. Output a single JSON object
with these four keys and nothing else. No explanation, no markdown fences.

  asset_roles   : object with one key per supplied asset name, in the order
                  listed, each set to "committed", "held_back" or "not_used"
  attempts_goal : true or false
  escalates     : true or false
  reduces       : true or false

------------------------------------------------------------------------------
1. asset_roles
------------------------------------------------------------------------------
You are given a list of asset names that appear in the plan. Give EVERY one of
them exactly one role, in the order listed. Use only names from the list.

  committed : the plan gives it a task toward the goal, at or before the step
              that attempts the goal, and the task does not wait on something
              going wrong.
  held_back : the plan keeps it in reserve, on standby, as a backup, fallback or
              contingency, or uses it only "if needed", "if required", or if a
              step fails.
  not_used  : anything else. The plan rules it out, declines it, only reports or
              lists it, only asks about it, uses it only after the goal is
              achieved, or uses it only in a branch for a different kind of
              casualty.

There is no default. Read what the plan says about each asset and decide. An
asset with a committed task anywhere in the plan is committed, even if it is
also mentioned as a backup somewhere else.

committed, however brief the task:
  "use TUG-002 to tow"                              -> TUG-002 committed
  "TUG-002 and TUG-005 make fast"                   -> both committed
  "rig TUG-004 aft"                                 -> TUG-004 committed
  "TUG-002 assists with the pull"                   -> TUG-002 committed
  "TUG-002 will be slow to arrive but take the bow line" -> committed
      A complaint about an asset is not a refusal to use it.
  "once TUG-005 is on scene, make fast and begin the pull" -> committed
      Waiting for an asset to ARRIVE is not waiting for something to go wrong.
  "TUG-002 tows; TUG-006 joins the pull when it arrives" -> both committed

held_back:
  "keep AHT-003 on standby in case the tow parts"   -> AHT-003 held_back
  "TUG-006 standing by to assist if required"       -> TUG-006 held_back
  "TUG-006 as a fallback should the pull fail"      -> TUG-006 held_back
  "TUG-002 tows; if that is not enough, add TUG-006" -> TUG-002 committed,
                                                       TUG-006 held_back
  "if the tow parts, bring in TUG-006"              -> TUG-006 held_back

not_used:
  "TUG-007 is too far out to be of use"             -> not_used
  "we will not use the lift bags"                   -> not_used
  "the ledger also lists CRN-002"                   -> not_used
  "TUG-009 could be requested later"                -> not_used
  "once she is afloat, TUG-009 escorts her to port" -> not_used
  Some plans branch over what happened to the vessel ("if aground ... if on
  fire ..."). Only the branch that pursues the goal word counts; an asset that
  appears only in another branch is not_used.

------------------------------------------------------------------------------
2. attempts_goal
------------------------------------------------------------------------------
You are given one goal word for this casualty, e.g. "refloat". True if some step
of the plan attempts THAT outcome for the casualty vessel, in any wording.

Match the OBJECT, not the verb. The goal must be done to the casualty.
  goal "refloat": "haul her off the bank on the rising tide"   -> true
  goal "refloat": "pull the vessel clear of the ground"        -> true
  goal "refloat": "survey the hull and report"                 -> false
      (preparation is not the outcome)
  goal "refloat": "tow the barge off the berth to clear room"  -> false
      (right verb, wrong object -- not the casualty)
  goal "extinguish": "cool the adjacent tanks"                 -> false
      (containment is not extinguishing)

DEFAULT: false. A plan that only prepares, surveys, requests or discusses has
not attempted the goal.

------------------------------------------------------------------------------
3. escalates
------------------------------------------------------------------------------
True if the plan states that the available resources are NOT ENOUGH for this
job in the time available, or asks for more resources (or hands the job to
someone else) BEFORE attempting it.
  "the assets on hand cannot generate the pull required"  -> true
  "recommend engaging a specialist salvor"                -> true
  "request additional tugs before attempting the refloat" -> true
  "if the refloat fails, request more tugs"               -> false
      (a request made only if the attempt fails is a contingency, not a
       statement that the resources fall short)
  "this will be difficult and conditions are marginal"    -> false
      (difficulty is not insufficiency)
  "monitor and reassess at the next tide"                 -> false

DEFAULT: false. Hedging, caution and risk language are not escalation. The plan
must say the resources fall short or that someone else must supply them.

------------------------------------------------------------------------------
4. reduces
------------------------------------------------------------------------------
True if the plan changes WHAT IS BEING ACHIEVED so that less capability is
needed -- lightening the casualty, removing cargo or ballast, waiting for a
higher tide, or settling for a partial outcome.
  "discharge No. 2 hold to lighten her before the pull"  -> true
  "deballast to reduce the ground reaction"              -> true
  "wait for spring tides for more water"                 -> true
  "beach her in shallow water rather than refloat"       -> true
  "pump out the flooded engine room to restore buoyancy" -> false
      (that is the refloat itself, not a smaller job)
  "take the strain slowly to avoid parting the tow"      -> false
      (method, not scope)

DEFAULT: false. A change of technique is not a change of scope.

------------------------------------------------------------------------------
escalates and reduces are independent. A plan may do both, either, or neither.
